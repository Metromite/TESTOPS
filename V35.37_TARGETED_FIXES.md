# DispatchOPS V35.37 — Targeted Fixes

This build keeps the existing Bulk Organizer, Price Change, federation/fallback, and pallet-capacity behavior intact while applying focused fixes:

- Mixed pallet display: physical pallet count is now shown separately from Big-equivalent capacity. Example: 8 Big + 8 Small = 16 physical pallets = 13.5 Big-equivalent.
- Bulk Organizer loading dialog, store/schedule invoice rows, waiting rows, batch loading, KPI area, and vehicle-loaded invoice rows show physical vs Big-equivalent values.
- Mixed invoice loading fallback correctly identifies Big/Small pallets by index even when `pallet_types` is absent but `big_pallets` / `small_pallets` are present.
- Bulk Organizer reads its Tertiary-owned plan/default data directly from Tertiary and operational master data directly from Primary to reduce unnecessary three-project waits.
- Federated generic reads now query the owning project for Price Change/Bulk/Department data and only federate true import/fact tables.
- Price Change admin bootstrap is lighter: initial campaign load no longer transfers all visits/items/assignments until a campaign is selected; selected campaign data is loaded separately and briefly cached for instant repeat navigation.
- Price Change Excel export starts progress immediately, downloads evidence concurrently, and compresses photos/signatures to modest JPEG quality/resolution when smaller output is possible.
- LOGI can inspect live Primary, Secondary and Tertiary application tables through the supported tool layer.
- LOGI writes require an admin username/password and server-side admin verification before any database mutation.
- Admin & Account Settings now manages application usernames, passwords, roles and active status.
- Login is database-backed with hashed passwords; the legacy `admin` and `user` credentials are preserved on a fresh migration, while passwords can be changed from Admin settings.

## Verification
