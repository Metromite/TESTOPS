# V35.47 — Bulk Organizer Restore + LOGI Best Driver Fix

## Bulk Organizer
- Restores the Bulk Organizer page behavior from the last stable V35.38 line instead of the later hydration/realtime redesign.
- Keeps the current mixed Big/Small pallet model: 1 Big = 1 Big-equivalent; 1 Small = 2/3 Big-equivalent.
- Primary is now the canonical daily planner source because the live historical planner data is in Primary.
- Tertiary remains a fallback for dates that exist only there.
- Realtime planner updates are read from Primary; Department Entry realtime remains on Tertiary.
- Empty planner shells cannot replace a populated Primary plan.
- No Bulk Organizer data migration or deletion is performed.

## September 24 verification
- Primary `bulk_organizer_plans` still contains the 2026-09-24 plan.
- That plan currently contains 2 stored invoices.
- The restore is intended to display those existing records instead of replacing them during date hydration/realtime updates.

## LOGI
- Live `logi-agent` is active at version 5.
- `drivers.performance_rating` is not queried.
- `driver_daily_divisions.driver_id` is normalized to `person_code` for legacy queries.
- If route assignment scores exist, LOGI can use `route_assignments.driver_score`.
- The current live database has no route assignment rows, so “Best Driver” falls back to SAP invoice volume and labels it as workload/volume, not a quality rating.
