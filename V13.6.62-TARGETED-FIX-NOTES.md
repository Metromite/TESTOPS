# DispatchOPS V13.6.62 — Targeted Scroll + Driver Performance Fix

## Scope
Only two reported issues were targeted:
1. Blank/scroll offset above the authenticated Top Menu after refresh, sign-in, or navigation.
2. Driver Performance behaving differently depending on which drivers are selected together.

## Scroll fix
- `GlassSidebarShell` now portals the authenticated TopNav directly to `document.body`.
- The nav remains viewport-fixed and is no longer inside `#root`/route content where a containing block or overflow/transition context could affect fixed positioning.
- `ProtectedLayout` now owns browser scroll restoration for authenticated routes:
  - `history.scrollRestoration = "manual"`
  - reset immediately
  - reset again on the next animation frame
  - reset once after 80ms for late auth/layout hydration
- Existing 58px layout spacer is retained so page content still starts below the fixed nav.
- Wallpaper code is untouched.

## Driver Performance fix
The root issue found in the local slicer flow was order-dependent selection state:
- Driver options are derived while other slicers are active.
- The previous Dashboard effect removed any selected driver that temporarily disappeared from the recalculated option list.
- This could silently turn a single selected driver into an empty selection or change the effective selection as another driver was added.

Changes:
- Selected driver values are no longer pruned when option lists recalculate.
- Driver filter matching is case-insensitive/trim-normalized locally.
- Driver option calculation uses the normalized driver key for the driver dimension while preserving all other slicer behavior.
- Fleet Directory remains display-only; selected slicer values are not rewritten to Fleet names.

## Preserved
- Existing local/offline Dashboard dataset architecture.
- Existing date-aware vehicle+driver route matching in Driver Performance.
- Existing multi-driver slicer UI.
- Existing wallpaper implementation.
- Other pages/features were not intentionally changed.

## Validation
- ZIP integrity should be checked with `unzip -t`.
- Full production TypeScript/Vite build could not be completed in the provided workspace because `frontend/node_modules` is absent. The global TypeScript compiler therefore reports missing installed packages rather than project-source dependency/type results.
