# DispatchOPS V13.6.61 — Targeted Scroll + Driver Performance Fix

## Scope
Only two regressions are addressed. Existing Dashboard data/cache/Supabase/KPI/chart behavior is preserved.

### 1. Global top navigation after refresh/sign-in
- The application top navigation is now a true viewport-fixed shell (`position: fixed; top: 0; left: 0; right: 0`).
- A matching 58px spacer remains in document flow so page content keeps its original visual starting position.
- This removes the refresh-only blank area above the navigation that can occur when sticky positioning/browser scroll restoration interact with the global shell.
- The fix is global because the same shell is shared by Dashboard and authenticated pages.
- Wallpaper remains a background layer and is not used to control navigation position.

### 2. Driver Performance slicer
- Removed the Dashboard-level conversion from selected slicer value -> Fleet Directory name.
- The local analytical dataset now receives the exact driver identifiers selected by the slicer.
- Fleet Directory remains display-only for labels.
- This prevents a Fleet display-name/SAP driver_name mismatch from turning a single-driver selection into zero rows or causing subsequent selections to appear cumulative.
- Existing date/vehicle-aware GPS route matching in `buildLocalDriverPerformance` remains intact.

## Intentionally untouched
- Supabase/federation/fallback architecture
- IndexedDB dashboard cache
- KPI calculations
- Slicers other than the driver identity fix
- Excel export
- Chart visual system
- Overview/other Dashboard tabs
- Bulk Organizer and other application pages' business logic
