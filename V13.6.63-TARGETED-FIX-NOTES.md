# DispatchOPS V13.6.63 — Scroll Regression Recovery + Driver Performance Scope Fix

## Why this version exists
V13.6.62 made the shell worse: the authenticated Top Menu disappeared while the blank scroll offset remained. This version is intentionally based on the V13.6.61 source tree but restores the pre-scroll-regression shell behavior instead of adding another fixed/portal layer.

## Scroll / Top Menu
- Restored the original `sticky top-0` TopNav in `GlassSidebarShell`.
- Removed the artificial `top-nav-spacer` from `ProtectedLayout`.
- Removed the forced global `position: fixed` TopNav CSS.
- Removed the global `overscroll-behavior-y: none` that was introduced in V13.6.59.
- Removed the Dashboard-only `useLayoutEffect` scroll forcing introduced in V13.6.60.
- Wallpaper implementation is untouched.
- This intentionally returns the shell/scroll mechanics to the pre-regression baseline while preserving later Dashboard data/chart/UI work.

## Driver Performance
The previous fix still had two structural problems:
1. `Dashboard.tsx` still pruned selected drivers when option lists were recalculated. That could silently change the selection during a multi-select interaction.
2. Driver Performance resolved GPS ownership using only the currently selected driver rows. That makes a shared vehicle look different depending on which drivers are selected together.

Changes:
- Selected driver state is now authoritative; option recalculation no longer deletes selected drivers.
- Driver filter matching uses normalized driver identity (trim/lowercase/Unicode punctuation normalization).
- Driver Performance first resolves route ownership against the full current date/other-filter scope with the driver dimension removed.
- Only after route ownership is resolved are the selected driver identities applied to the route cards.
- This prevents adding/removing another driver from changing whether an already-selected driver's vehicle route is considered ambiguous.
- Route date + vehicle ownership logic remains intact.
