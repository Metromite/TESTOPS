# DispatchOPS V13.1 Fixes

- LOGI no longer exposes provider/model/API-key failures to the user.
- LOGI ignores the accidental `supabase-data` + API-key combination instead of routing it to OpenAI with `gpt-4o-mini`.
- Provider models now have provider-specific defaults.
- LOGI has a deterministic live-data fallback for Best Helper, invoice, Experience, and import questions.
- Best Helper uses the same live Route Planning / Experience factors instead of persisted zero helper_score values.
- LOGI catalog routing covers Primary, Secondary, and Tertiary without per-message 120-request schema discovery.
- SAP raw-row inserts now use concurrent chunks with progress callbacks.
- SAP driver/helper daily-division upserts are batched instead of one request per person/day.
- Import history is federated across Primary, Secondary, and Tertiary.
- View reads the owning database.
- Admin Delete is beside View and removes the source object plus raw rows, parsed facts, and batch metadata after confirmation.
- Existing Bulk Organizer code was not intentionally changed by these fixes.
